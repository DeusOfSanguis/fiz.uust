# Pacer Log

Приложение, которое превращает ссылки из Pacer в таблицу. Сделано под телефон, но
ограничений по устройствам нет: с компьютера тоже открывается.

1. принимает ссылку (или текст «поделиться») из Pacer;
3. вытаскивает со страницы тренировки дату, километраж, время;
4. **не даёт редактировать данные** — только то, что реально на странице Pacer;
5. **фильтрует и считает**: короче 3 км — не добавляет, длиннее 6 км — в зачёт идёт 6 км
   (фактические видны в скобках);
6. **надёжно сохраняет** записи в телефоне (а с сервером — ещё и в файле с бэкапами);
7. по запросу отдаёт **Excel (.xlsx)** или CSV, где есть и километраж, и время, и ссылка,
   и накопительный итог «сколько уже найдено».

## Правила учёта

| Ситуация | Что происходит |
| --- | --- |
| Прогулка **меньше 3 км** | В журнал не попадает. Приложение пишет: «2,40 км — меньше 3 км, такая прогулка в журнал не попадает». |
| Прогулка **3–6 км** | Попадает как есть. |
| Прогулка **больше 6 км** | В списках и приложении видно `6,00 (9,35)`: 6 км идут в зачёт, фактические — в скобках. В журнале хранятся настоящие километры. |
| «Всего найдено» | Сумма зачётных километров. В приложении — в шапке, в колонке «Всего» и в подвале; в Excel — колонка «Всего найдено (км)» и жирная строка итогов снизу. |

Правила применяются и к уже сохранённым записям, поэтому цифры в приложении и в файле
всегда сходятся. Записи, сделанные вручную (без ссылки на Pacer), при загрузке отбрасываются.

## Данные только правдивые

Редактирования нет: нельзя ни ввести тренировку руками, ни поправить километраж или время.
Запись создаётся только разбором страницы Pacer. Остаётся единственное действие — **удалить**
ошибочную запись (например, если Pacer поменял вёрстку и данные распознались неверно).

## APK для Android (без интернета)

Помимо сайта, приложение можно установить как обычное приложение Android:

1. Откройте вкладку **Actions** в репозитории → **Build Android APK** → **Run workflow**.
2. Через 5–8 минут внизу страницы сборки появится файл **pacer-log-apk** — скачайте его.
3. Откройте APK на телефоне (разрешите установку из неизвестных источников) — готово.

Внутри APK всё уже на телефоне: журнал, подсчёты и Excel работают **без интернета**.
Сеть нужна только чтобы скачать новую страницу Pacer — и если её нет, приложение честно
скажет «Нет интернета», а ссылка останется в очереди.

Приложение ставится как «Pacer Log», понимает «Поделиться» из Pacer (ссылка сразу попадает
в журнал) и открывает ссылки `share.mypacer.com` прямо в себе.

**Подпись.** Без настройки собирается debug-APK: он устанавливается, но каждая новая
сборка потребует удалить предыдущую (данные при этом пропадут — сначала сделайте «Копию JSON»).
Чтобы обновления ставились поверх, один раз создайте ключ и добавьте секреты:

```bash
keytool -genkey -v -keystore release.keystore -alias pacer \
  -keyalg RSA -keysize 2048 -validity 10000
base64 -w0 release.keystore    # вставить в секрет KEYSTORE_BASE64
```

Секреты репозитория: `KEYSTORE_BASE64`, `KEYSTORE_PASSWORD`, `KEY_ALIAS`, `KEY_PASSWORD`.
После этого сборка сама подпишет release-APK.

Собрать локально (нужны JDK 21 и Android SDK):

```bash
npm ci && npm run apk          # debug-APK: android/app/build/outputs/apk/debug/
npm run apk:release            # release-APK (нужна подпись)
```

## Как дать приложение группе

**У каждого участника свой журнал** — так решили, и это самый простой вариант:
не нужен сервер, база и пароли. Участнику достаточно ссылки.

### GitHub Pages (бесплатно, уже настроено)

В репозитории лежит `.github/workflows/deploy.yml`: при обновлении `main` приложение
само собирается, прогоняет тесты и публикуется.

1. Сделать репозиторий **публичным** (Settings → General → Danger Zone → Change visibility).
2. Settings → **Pages** → Source: **GitHub Actions**.
3. Смержить этот PR в `main` — сборка запустится сама.
4. Через минуту ссылка готова: `https://<ваш-логин>.github.io/fiz.uust/`.

Дальше каждый участник: открыл ссылку на телефоне → меню браузера → **«Установить
приложение»** (Chrome) или **«На экран Домой»** (Safari) → в Pacer «Поделиться» → Pacer Log.

### Другие бесплатные варианты

| Куда | Что делать | Особенность |
| --- | --- | --- |
| **Cloudflare Pages** | подключить репозиторий, build command `npm run build`, output `dist` | в репозитории есть `functions/api/fetch.ts` — Cloudflare будет сам скачивать страницы Pacer, прокси не нужны |
| **Netlify** | build `npm run build`, publish `dist` | работает из коробки, без прокси-функции |
| **Vercel** | framework: Vite | работает из коробки |

Приложению нужен **HTTPS** — без него не установится как приложение и не появится
«Поделиться» из Pacer. Все перечисленные хостинги дают HTTPS автоматически.

### Если когда-нибудь захочется общий журнал

Тогда понадобится сервер: `docker build -t pacer-log . && docker run -d -p 4173:4173 -v pacer-data:/data pacer-log`
(или `npm ci && npm run build && npm start`). Появится общий файл `data/pacer-log.json`
с бэкапами — приложение само его подхватит и будет синхронизировать записи между телефонами.

### Про прокси к Pacer

Браузер не может запросить `share.mypacer.com` напрямую (CORS), поэтому без своего
сервера страница тянется через публичные прокси. Они бесплатные и иногда тормозят:
если ссылка не загрузилась — она останется в очереди, жмите «Продолжить» позже.

## Сохранность данных (главное)

Таблица собирается месяцами, поэтому потерять запись негде:

| Что защищает | Как работает |
| --- | --- |
| **Файл на диске** (если есть сервер) | Каждое изменение пишется в `data/pacer-log.json` (атомарно, через временный файл — не бывает «полуфайлов»). |
| **Бэкапы** (если есть сервер) | Перед каждой перезаписью предыдущая версия уезжает в `data/backups/pacer-log-…json`, хранится 30 последних. |
| **Телефон** | Журнал лежит в памяти приложения: работает и без интернета, и без сервера. |
| **Слияние, а не перезапись** | При запуске локальный и серверный журналы объединяются по тренировке; побеждает более свежая версия. Ничего не затирается. |
| **Незавершённая очередь** | Ссылки, которые ещё не загрузились, хранятся в браузере. Закрыли вкладку на 7-й из 20 — при следующем открытии кнопка «Продолжить» докачает остальные. |
| **Резервная копия** | Кнопка «Копия JSON» скачивает файл; «Импорт» загружает его обратно и **сливает** с текущим журналом. |
| **Индикатор** | В шапке видно: «Сохранено · 14:32» (сервер) или «В этом телефоне» — сразу понятно, куда пишутся данные. |

> Без сервера записи живут только в телефоне: очистили данные браузера или сменили
> телефон — журнал пропал. Поэтому раз в неделю жмите «Копия JSON»: файл сохранится
> в «Загрузках», а кнопкой «Импорт» его можно вернуть на новом телефоне.

## Как пользоваться

1. Откройте приложение на телефоне и добавьте его на домашний экран.
2. В Pacer: тренировка → **Поделиться** → **Скопировать ссылку**
   (`https://share.mypacer.com/track/OXxdWKozfoIOzHAnr4OLFE`).
3. Вставьте ссылку в поле «Добавить тренировку». Можно сразу несколько — по одной в строке.
4. Запись появляется в списке и сразу сохраняется (в телефоне, а с сервером — ещё и в файле).
5. В конце месяца — **Скачать Excel (.xlsx)**.

Если ссылка не разобралась, добавить запись вручную нельзя — данные берутся только из Pacer.
Ссылка останется в очереди, её можно повторить позже.

### «Поделиться» с телефона

Приложение — PWA с [share target](https://developer.mozilla.org/en-US/docs/Web/Manifest/share_target):
после установки в системном меню «Поделиться» появляется Pacer Log, и ссылка уходит
в приложение сама. Нужен HTTPS (или localhost) и установленное приложение.

## Что попадает в таблицу

| Колонка | Пример | Примечание |
| --- | --- | --- |
| Дата и время | `20.10.2026 07:37` | настоящая дата Excel (`yyyy-mm-dd hh:mm`) |
| Километраж (км) | `6,80` | мили переводятся в километры |
| Время (ч:мм) | `2:56` | настоящая длительность Excel `[h]:mm` — суммируется, >24 ч не ломается |
| Ссылка | `https://share.mypacer.com/track/…` | исходная ссылка |
| Всего найдено (км) | `10,00` | накопительный итог: сколько уже набрано |

Плюс колонка **Фактически (км)** — заполняется только там, где реальные километры больше
зачётных (то есть когда стоит потолок 6 км).

Галочка в блоке «Экспорт» добавляет **Активность**, **Шаги**, **Калории**, **Набор высоты (м)**.

CSV выгружается с `;` и BOM — Excel открывает без «кракозябр» в русской и нидерландской локали.

## Откуда берутся данные

Страница `share.mypacer.com/track/<id>` отдаётся уже с готовыми числами, поэтому парсер
работает по её тексту (HTML → текст), а не по хрупким CSS-селекторам. Понимает английские
и русские подписи (`Time` / `Время`, `Distance` / `Дистанция`), метры и мили, даты
`Oct 20, 2026 7:37 AM`, `20.10.2026 19:41` и ISO.

Загрузка идёт по цепочке, пока источник не даст валидные данные:

1. **свой сервер** `/api/fetch` — быстро и без лимитов (есть в `dev`, `preview`, `start`);
2. **публичные CORS-прокси** (`corsfix`, `allorigins`, `codetabs`, `cors.lol`, `r.jina.ai`) —
   нужны, если приложение открыто как статичный сайт.

Если ни один не ответил, в интерфейсе видно, что пробовали, а ссылка остаётся в очереди
для повтора.

> Публичные прокси — чужие бесплатные сервисы: могут тормозить и вводить лимиты.
> Для регулярного использования запускайте `npm start`.

## API хранилища

```
GET  /api/entries            -> { entries, savedAt, storage: 'file' }
PUT  /api/entries            <- { entries }            (полная замена)
POST /api/entries            <- { entries, mode:'merge' } (слияние с серверным списком)
```

`data/` и `data/backups/` не попадают в git (см. `.gitignore`) — это ваши данные.

## Структура проекта

```
src/
  lib/pacer.ts     поиск ссылок, загрузка страницы, парсер
  lib/store.ts     журнал в localStorage + импорт резервных копий
  lib/sync.ts      синхронизация с файлом на сервере, слияние
  lib/queue.ts     незавершённые ссылки (переживают перезапуск)
  lib/xlsx.ts      генератор .xlsx (zip + OOXML, без зависимостей)
  lib/export.ts    колонки, xlsx/csv/json
  lib/format.ts    дата, время ч:мм, длительность
  components/      панель добавления, таблица, формы, экспорт, тосты
server/store.mjs   файловое хранилище + бэкапы + HTTP-обработчик /api/entries
server.mjs         продакшн-сервер: статика, прокси к Pacer, хранилище
tests/             парсер, загрузка, хранилище, очередь, Excel, UI (jsdom)
```

## Ограничения

- Если Pacer поменяет вёрстку, парсер может перестать находить поля — запись нельзя
  добавить руками, зато можно повторить загрузку позже. Тесты на реальном HTML лежат
  в `tests/fixtures/`.
- Время суток на странице Pacer зависит от часового пояса того, кто её открыл; сторонние
  прокси могут его сместить (дата почти всегда верная). Свой сервер отдаёт так, как
  увидели бы вы.
- Синхронизации между устройствами нет (у каждого свой журнал), но есть «Копия JSON» + «Импорт».
- APK подходит для Android; на iPhone — сценарий «Добавить на экран Домой» из Safari
  (там приложение тоже работает офлайн, но без приёма «Поделиться»).
